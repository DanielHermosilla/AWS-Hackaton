# Logo de ZMD Mobility

Recupera el nombre y los acuerdos de marca existentes; `docs/CONTEXTO.md` es la referencia del proyecto. ZMD Mobility es la consultora y CASE es la empresa del desafío. Una referencia Apple/Notion expresa claridad y cuidado, no permiso para reproducir sus marcas.

Distingue explorar conceptos, refinar una dirección y preparar un activo existente. Reutiliza el brief y las decisiones disponibles. Pregunta solo lo que cambie el resultado; para avanzar una exploración reversible puedes explicitar supuestos. No impongas un cuestionario, un número de propuestas ni un paquete completo de identidad cuando se pidió una pieza.

Para un logo de interfaz, favorece una forma vectorial sencilla: proporción, espacio negativo, silueta y tipografía antes que efectos. Busca una relación defendible con la marca; un rayo, auto o pin no es obligatorio por tratarse de movilidad. Si comparas conceptos, cambia la idea o composición, no solo el color.

Construye SVG real con formas y trazados editables cuando ese sea el formato adecuado. Una imagen raster incrustada en un SVG sigue siendo raster. La generación de imágenes disponible puede apoyar exploración si aporta valor; no necesita convertirse en dependencia del logo ni justificar otro servicio externo.

Al construir o exportar SVG, consulta [integración y comprobación](references/svg-entrega.md). Produce solo las variantes necesarias para los usos solicitados y conserva un original editable. Comprueba el resultado renderizado en el tamaño y fondo en que se utilizará; un XML válido no demuestra legibilidad ni calidad visual. Ajusta ópticamente cuando haga falta, sin aplicar tamaños mínimos universales.

Entrega los activos y una vista previa revisable con una explicación breve de la dirección y lo comprobado. Diferencia propuesta de marca aprobada. No presentes una revisión visual como búsqueda de marcas registradas o garantía de exclusividad.
